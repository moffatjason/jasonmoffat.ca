Always Geeky Games · Unity 6 · Steam, Windows and macOS · 2026

Co-creator, game director, lead engineer

A top-down action roguelike about cultivating strange flora between combat runs. Started as a personal prototype and reached a live Steam page in seven months with a small team.

01Combat. Stamina-gated block, parry, and counter on tight timing windows, against enemies that telegraph before they swing.
02Procedural levels. Voxel models from the artist become tile sets that assemble into dungeon rooms at runtime, with editor tools so nobody hand-places a room.
03Gamepad-first UI. One UI Toolkit design system across every screen, with the focus and input-prompt rules enforced by tests so they never regress.
04A base-building sim between runs. Grow and process the flora you bring back, presented as a bank of retro-CRT terminals.
05Shipping. Every merge builds Windows and macOS and deploys to a Steam branch, with test suites gating the rules that matter.
06An AI-assisted workflow. Project skills, reference docs, and the Unity editor driven over MCP, all built in-house. It's how a small team moves this fast.

Approach

Systems and pipelines first

Building the tool that makes the next hundred assets cheap beats hand-placing the first ten. Voxel importers, tileset authoring, level editors, and content pipelines show up in every role so far.

Standards that enforce themselves

On Hyperflora the UI focus rules, input-prompt rules, economy shape, and save isolation are all EditMode tests. If a rule matters, it should fail a build, not live in a wiki.

AI as part of the pipeline

Claude Code runs against the Unity editor through MCP, with project skills and reference docs that encode how the codebase works. It changed what the team can ship.
